# orthopro-catalogo

Branch: `feat/catalogo` (from `main` at `2141061`)

## Objective
A real service catalog stored in PostgreSQL and managed by administrators: each service has **name, value (price), description and an image** uploaded to **Cloudinary** (only the resulting URL is stored in the DB). The public website renders its catalog pages (`apps/web/app/catalogo/*`) from this catalog, and the **catalog PDF is generated by the backend** from the active services, with the website's dark background, typography (Outfit headings, Poppins body) and color palette.

## User decisions (given)
- Per service: nombre, valor, descripcion, imagen (uploaded to Cloudinary; the DB keeps the link).
- The catalog is the source for `apps/web/app/catalogo/`.
- The PDF is built in the backend from the product list; background = the web's background color (`#171717`), same typography and palette.
- Existing rule (earlier decision): prices are NEVER shown on the website; they are only inside the downloadable PDF ("Ver precios").

## Design defaults chosen by the parent
- **Schema** (migration on `servicio`): add `slug` (unique, generated from the name, needed by the existing `/catalogo/[servicio]` routes), `imagen_url` (text, nullable), `imagen_public_id` (text, nullable; needed to replace/delete the asset in Cloudinary). Seed the 4 current service lines (names/descriptions from `apps/web/lib/catalog.ts`) with a PROVISIONAL price of `0.00`; the PDF shows "Consultar valor" while the price is 0. Real prices are entered by an administrator.
- **API** (module `src/catalogo`):
  - Public (`@Public()`, throttled): `GET /catalogo/servicios` and `GET /catalogo/servicios/:slug` return ONLY `{ id, slug, nombre, descripcion, imagenUrl }` of ACTIVE services (never `precio`), `Cache-Control` short public cache; `GET /catalogo/pdf` returns the generated PDF (`application/pdf`, `Content-Disposition: attachment; filename="catalogo-orthopro-lab.pdf"`), strict throttle.
  - Admin (`@Roles('administrador')`): `GET/POST /admin/catalogo/servicios`, `GET/PATCH/DELETE /admin/catalogo/servicios/:id` (full fields incl. `precio` as a numeric string with 2 decimals, `activo`; delete = soft delete via `activo=false` unless it has no `detalle_orden` rows, document the rule), `POST /admin/catalogo/servicios/:id/imagen` (multipart, field `imagen`).
  - Validation: `class-validator` DTOs; `precio` regex `^\d{1,10}(\.\d{1,2})?$`; nombre 2-120; descripcion up to 2000; image: JPEG/PNG/WebP only, max 5 MB, verified by magic bytes (not only the declared mimetype), safe filename handling; replaced/deleted images are removed from Cloudinary (best effort, logged on failure).
- **Cloudinary**: official `cloudinary` SDK v2 behind an `ImageStorage` port (`upload`, `delete`) with a Cloudinary adapter and a fake for tests. Env (all optional in dev; if missing the upload endpoint returns `503` with a clear message and the rest of the API keeps working): `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, `CLOUDINARY_FOLDER` (default `orthopro/catalogo`). Stored URL must be an `https://res.cloudinary.com/<cloud_name>/...` URL (validated before saving and before fetching it for the PDF: SSRF guard).
- **Remote-operation rule**: real uploads to Cloudinary need the user's credentials; writers must NOT call Cloudinary for real (no credentials are available to them and they must never read `.env`). Tests use the fake storage; the real upload is verified by the user with the documented command.
- **PDF** (`pdfkit`): every page filled with `#171717`; Outfit (headings) and Poppins (body) TTF files embedded from the repo (`apps/api/assets/fonts/`, OFL licensed; take them from a trustworthy source and record the license); palette from `@repo/theme`: body `#f5f5f5`, titles `#56898f`, highlight `#48fbc1`, muted `#b6bebf`, raised surface `#1f2425`. Cover (brand "OrthoPro Lab", "Laboratorio dental en Medellin", address `Cl. 53 #43 - 43, oficina 204, Medellin`, update date), one block per active service (image, name, description, value formatted in COP, "Consultar valor" if 0), footer with page numbers. Service images are fetched server-side from Cloudinary (JPEG via `f_jpg,w_...` transformation, timeouts, size cap, host allow-list) and degrade gracefully when missing. Cache the generated PDF (Redis, keyed by a hash of the catalog state: ids + `fecha_actualizacion` + image urls) and regenerate when the catalog changes.
- **Web**: `apps/web/app/catalogo/*` and the landing services read from `GET /catalogo/servicios` (server-side fetch with `"use cache"` + `cacheLife` + `cacheTag`, `cacheComponents` is on), `generateStaticParams` from the API, graceful fallback when the API is unreachable at build time, `sitemap.ts` and JSON-LD built from the same data, "Ver precios" points to the API PDF endpoint, remove the static placeholder PDF. The service detail pages show name, description and image (the old per-product item lists disappear because the new model has no items).
- **Admin portal**: `/catalogo` of `apps/admin` stops using sample data: list/create/edit/deactivate services and upload/replace the image, calling the admin endpoints through `@repo/api-client`.
- Hard rules for writers: never read/print/edit `.env*` (only `.env.example`), never run `keys:generate`, never touch processes you did not start (the user may have dev servers on 3000-3003; use isolated ports 3101-3103), kill by PID only, never `pkill -f`.
